# EXQ-001: Candidate-scope data qualification protocol

EXQ-001 evaluates only the seven AF-002 candidates frozen by AF-003 and the
equal_weight_zscore simple diagnostic. It does not evaluate every Alpha158
field, create a portfolio, consume CSI500, access a network provider, or change
the sealed-store permissions.

The runner binds DEV-001's resolved contract, evidence, staged-view pin,
AF-003 result, the archived five-boundary membership correction, and the frozen
free-evidence residual, interval, and funnel objects by SHA-256. It then derives
the required raw fields from the registered expressions, uses actual corrected
membership at signal date T, and expands each residual key through factor
lookback plus label T+1/T+2 dependencies. Only exact intersecting keys are
retained; the other 540 free-evidence residuals remain frozen and are not
re-investigated.

The three allowed top-level outcomes are QUALIFIED_FOR_PORTFOLIO_RESEARCH,
QUALIFIED_WITH_EXCLUSIONS, and BLOCKED_DATA. The current pinned Qlib dataset
declares adjusted prices, has no officially verified corporate-action evidence,
and explicitly forbids execution use. The approved DEV-001 view also excludes
raw OHLCV and has no ST, T+1 execution price, price-limit, board-lot, liquidity,
or cost evidence. Accordingly, a successful EXQ-001 run is expected to record
BLOCKED_DATA unless independently archived, scope-bound evidence is already
present.

Neither this outcome nor a future scoped qualification changes
FORMAL_PIT_STATUS=BLOCKED_DATA, FORMAL_RESEARCH_STATUS=BLOCKED_DATA, or
CSI500=NOT_STARTED.
